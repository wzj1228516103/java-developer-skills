# Java 核心规则

## MUST

- `equals` 与 `hashCode` 成对实现；包装类型比较使用 `Objects.equals`，不要用 `==`。
- 金额、税率、计费等十进制业务使用 `BigDecimal` 或项目约定的最小货币单位；避免 `double` 直接计算和比较。
- 时间优先使用 `java.time`，明确时区；共享格式器使用不可变的 `DateTimeFormatter`。
- 不返回 `null` 集合；根据调用方需要返回不可变空集合或可变集合。
- 资源、锁和临时状态必须在所有路径释放；不要吞掉异常。

## SHOULD

- 用有业务含义的名称和具名常量替代魔法数字；方法保持单一职责，但不要机械按行数拆分。
- 选择与访问模式匹配的集合；共享可变状态必须有明确的线程安全策略。
- 优先构造不可变对象；`Optional` 主要用于返回值，不要用于实体字段、序列化 DTO 或方法参数，除非项目已有约定。

## 常见风险

`SimpleDateFormat` 共享、字符串 `==`、循环内字符串 `+`、裸建线程、空 `catch`、用 `HashMap` 作为跨线程共享状态。
